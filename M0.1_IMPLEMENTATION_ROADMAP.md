## Testing Strategy for Remaining Tasks

### Unit Tests (per subtask)
- Channel operations, step logic, adapter connectivity
- No external I/O mocking needed; use real temp files

### Fixture Tests (reusable)
- Live in `test/fixtures/step_name.yaml`
- Define input → expected output across all steps
- Run via `midctl test`

### Integration Tests
- End-to-end YAML route → real message flow
- Use in-process HTTP listener + temp file
- Race-detector enabled from M0.2, but good practice now
