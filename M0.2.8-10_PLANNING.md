## M0.2.8: Fixture Test Runner

**Purpose:** Declarative integration test framework for config-driven testing

**What it does:**
- Load test fixtures from YAML files
- Execute middleware against test inputs
- Verify outputs, errors, retry behavior
- Report coverage and failures

**Configuration Example:**
```yaml
# tests/fixtures/route-filter.yaml
fixtures:
  - name: "premium-tier filters correctly"
    input: { tier: "premium", amount: 1000 }
    expected_output: { name: "Alice", total: 1100 }
    expected_route: "premium-processing"
    
  - name: "dropped messages don't appear"
    input: { amount: -50 }
    expected_dropped: true
```

**CLI:**
```bash
midctl test examples/tests/
# Output: "15 fixtures passed, 2 failed, 1 timeout"
```

**Dependencies:** None (pure testing layer)  
**Estimated Effort:** 3-4 hours  
**Tests Needed:** 8-10 fixture validation tests

## M0.2.9: Message Ordering Guarantees

**Purpose:** Preserve message order for ordered sources (databases, ordered queues)

**What it does:**
- Optional per-route ordering mode
- Serializes processing for ordered routes
- Parallel processing for unordered routes
- No performance penalty for unordered messages

**Configuration Example:**
```yaml
routes:
  ordered-processing:
    from: ordered-source
    ordering: required  # ← NEW
    steps:
      - filter: { expr: "status != 'cancelled'" }
```

**Implementation Strategy:**
- Add `Ordering` field to RouteConfig
- Constrain ordered routes to 1 worker (via executor config)
- Add ordering mode detection
- Document when to use (replaying events, state machines)

**Dependencies:** M0.2.1 (worker pools) — constraint to 1 worker  
**Estimated Effort:** 2-3 hours  
**Tests Needed:** 5-6 ordering verification tests

## M0.2.10: Observability (Metrics & Tracing)

**Purpose:** Production monitoring with Prometheus metrics and OpenTelemetry tracing

**What it does:**
- Per-route message counts, latencies, errors
- Retry attempt tracking
- Worker pool utilization metrics
- Distributed trace context propagation
- Dead-letter envelope tracking

**Metrics Exposed:**
```prometheus
# Prometheus format (localhost:2112/metrics)
dim_messages_total{route="premium-processing",status="success"} 1500
dim_message_latency_ms{route="premium-processing",quantile="0.99"} 45
dim_retries_total{route="premium-processing"} 32
dim_workers_in_flight{route="premium-processing"} 3
dim_dead_letters_total{route="premium-processing"} 5
```

**OpenTelemetry Spans:**
```
span: message_processing
  ├─ span: step_execution (filter)
  │   └─ span: filter_evaluation
  ├─ span: step_execution (translate)
  │   └─ span: translate_evaluation
  └─ span: output_write
```

**Configuration:**
```yaml
version: 1
observability:
  metrics:
    enabled: true
    prometheus_addr: ":2112"
  tracing:
    enabled: true
    otel_exporter: "stdout"  # or "jaeger", "datadog"
    sample_rate: 0.1  # 10% sampling
```

**Dependencies:** None (metric collection is orthogonal)  
**Estimated Effort:** 4-5 hours  
**Tests Needed:** 10-12 metric/trace validation tests
