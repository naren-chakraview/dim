- Shared input channel distributes work fairly

### M0.2.2: Retry Logic ✅
**Purpose:** Handle transient failures with exponential backoff  
**What it does:**
- Classifies errors (transient vs. permanent)
- Exponential backoff with jitter
- Max attempts configurable per route
- Dead-letter envelope tracks retry attempts

**Stats:** 20+ tests, 3-4 hrs implementation

**Configuration:**
```yaml
retry:
  max_attempts: 3
  backoff_ms: 1000
  jitter_ms: 100
```

**Impact:** Automatic failure recovery without code changes

---

### M0.2.3: Route Step ✅
**Purpose:** Content-based message routing  
**What it does:**
- Evaluate JSONata expression → case name
- Map cases to target routes/sinks
- Default fallback for unmatched cases
- Updates Metadata.Route for multi-route support

**Stats:** 24 tests, 2-3 hrs implementation

**Configuration:**
```yaml
- route:
    expr: "status"
    cases:
      "premium": route_vip
      "standard": route_normal
    default: route_fallback
```

**Impact:** Enables conditional routing without extra adapters

---

### M0.2.4: Wiretap Step ✅
**Purpose:** Non-blocking message duplication  
**What it does:**
- Copy to secondary sink (audit log, monitoring)
- Non-blocking (doesn't wait for tap sink)
- Tap failures don't block main pipeline
- Independent message copy

**Stats:** 13 tests, 1-2 hrs implementation

**Configuration:**
```yaml
- wiretap:
    sink: audit_log
```

**Impact:** Enables observability without pipeline impact

---

### M0.2.5: Idempotent Step ✅
**Purpose:** Suppress duplicate messages  
**What it does:**
- Extract dedup key via JSONata expression
- In-memory set with TTL-based eviction
- Drop duplicates, pass unique messages
- Bounded memory with warnings

**Stats:** 14 tests, 2-3 hrs implementation

**Configuration:**
```yaml
- idempotent:
    key_expr: "transaction_id"
    ttl_minutes: 60
```

**Impact:** Automatic deduplication without distributed coordination (Phase 3+)

---

### M0.2.6: Authorize Step ✅
**Purpose:** RBAC/ABAC policy enforcement  
**What it does:**
- RBAC: check principal.Roles
- ABAC: evaluate JSONata predicates
- Authorization failures are permanent (don't retry)
- Principal propagation from HTTP headers

**Stats:** 22 tests, 3-4 hrs implementation

**Configuration:**
```yaml
# RBAC
- authorize:
    mode: rbac
    require_roles: [admin, processor]

# ABAC
- authorize:
    mode: abac
    expr: "principal.roles contains 'admin' || principal.dept == 'finance'"
```

**Impact:** Declarative authorization without code

---

### M0.2.7: Multi-Route Support ✅
**Purpose:** Multiple independent pipelines from single config  
**What it does:**
- Parse multiple routes from YAML
- Shared HTTP source routes to correct executor
- Independent lifecycle per route
- Coordinated shutdown of all routes

**Stats:** 7 tests, 4-5 hrs implementation

**Configuration:**
```yaml
routes:
  route1:
    from: http-source
    auth: none
    error_path: { target: errors }
    steps: [...]
  
  route2:
    from: http-source
    auth: none
    error_path: { target: errors }
    steps: [...]
```

**HTTP Routing (3-level priority):**
1. X-Route header: `curl -H "X-Route: route1" ...`
2. Query param: `curl "...?route=route1" ...`
3. Path component: `curl .../ingest/route1 ...`

**Impact:** Single middleware instance handles multiple independent pipelines

## Architecture Overview

### Complete Pipeline Flow

```
HTTP Request (port 8080)
    ↓
HTTP Source Adapter
    ├─ Parse route (X-Route, query, path)
    ├─ Create Message with correlation ID
    └─ Route to correct executor
    ↓
Message Router (multi-route support)
    └─ Send to executor's input channel
    ↓
Worker Pool Executor (M0.2.1)
    ├─ 1-N concurrent workers
    ├─ Work distribution via channel FIFO
    └─ In-flight counter for backpressure
    ↓
Step Pipeline (M0.2.3-6):
    ├─ Route: Branch to different outputs
    ├─ Filter: Drop messages (predicate)
    ├─ Translate: Transform body (JSONata)
    ├─ Wiretap: Copy to audit log (non-blocking)
    ├─ Idempotent: Dedup via key (TTL eviction)
    └─ Authorize: Check principal (RBAC/ABAC)
    ↓
Step Execution with Retry (M0.2.2)
    ├─ Transient error → retry with backoff
    └─ Permanent error → dead-letter envelope
    ↓
Output:
    ├─ Success: File sink (JSONL)
    └─ Error: Error sink (dead-letter envelope)
```

### Concurrency Model

```
HTTP Source
    ↓ (incoming requests)
Message Router (route detection)
    ↓ (route-specific executor)
Worker Pool (1-N workers)
    ├─ Worker 1: executing step pipeline
    ├─ Worker 2: executing step pipeline
    ├─ Worker 3: executing step pipeline
    └─ Worker N: executing step pipeline
    ↓ (output channel)
File Sink (JSONL append mode)
```

## Configuration & Usage

### Simple Single Route

```yaml
version: 1

sources:
  http-source: { type: http }

sinks:
  output: { type: file, path: ./output.jsonl }
  errors: { type: file, path: ./errors.jsonl }

routes:
  main:
    from: http-source
    auth: none
    error_path:
      target: errors
      retry:
        max_attempts: 3
        backoff_ms: 1000
    steps:
      - filter:
          expr: "amount > 0"
      - translate:
          expr: "{name: name, total: amount * 1.1}"
```

### Complex Multi-Route with Authorization

```yaml
version: 1

sources:
  http-source: { type: http }

sinks:
  premium-out: { type: file, path: ./premium.jsonl }
  standard-out: { type: file, path: ./standard.jsonl }
  audit-log: { type: file, path: ./audit.jsonl }
  errors: { type: file, path: ./errors.jsonl }

routes:
  premium-processing:
    from: http-source
    auth: none
    error_path: { target: errors }
    steps:
      - authorize:
          mode: rbac
          require_roles: [premium-handler]
      - filter: { expr: "tier == 'premium'" }
      - wiretap: { sink: audit-log }
      - idempotent: { key_expr: "transaction_id", ttl_minutes: 60 }
      - route:
          expr: "status"
          cases:
            "urgent": urgent-handler
            "normal": normal-handler
          default: standard-handler

  standard-processing:
    from: http-source
    auth: none
    error_path: { target: errors }
    steps:
      - filter: { expr: "tier == 'standard'" }
      - translate: { expr: "{name: name, amount: amount}" }
```

### CLI Usage


## Error Handling & Retry Strategy

### Error Classification

| Error Type | Transient? | Action |
|-----------|-----------|--------|
| Timeout | Yes | Retry with backoff |
| Connection refused | Yes | Retry with backoff |
| Context deadline exceeded | Yes | Retry with backoff |
| Validation error | No | Dead-letter (permanent) |
| Authorization denied | No | Dead-letter (permanent) |
| Not found (404) | No | Dead-letter (permanent) |
| Unknown error | No | Dead-letter (fail-safe) |

### Retry Behavior

```
Attempt 1: immediate
Attempt 2: wait 1000ms + jitter
Attempt 3: wait 2000ms + jitter
Attempt 4: wait 4000ms + jitter
...
Max attempts reached → dead-letter envelope

Dead-letter envelope includes:
- Original message
- Error message
- Failed step index & type
- Retry attempt count
- Timestamp
```

## Architecture Decisions

### Why Worker Pools?
- Enable concurrent processing for independent messages
- Fair work distribution via Go channel scheduler
- Bounded memory (no unbounded goroutine creation)
- Graceful backpressure via bounded input channel

### Why Exponential Backoff?
- Standard practice for transient failures
- Prevents overwhelming struggling services
- Configurable jitter prevents thundering herd
- Capped at 30s to prevent excessive delays

### Why Multi-Route as Separate Step?
- Reuse existing executor & worker pool infrastructure
- Message routing orthogonal to processing
- Support future dynamic routing (metadata-based)
- Clean separation: routing vs. processing

### Why Idempotent as Step (not middleware)?
- Flexibility: apply at any point in pipeline
- Can use different dedup keys per route
- Pluggable: can disable for low-value flows
- Testable: isolated unit with clear behavior
