## M0.2.3: Route Step (Content-Based Router)

**Purpose:** Branch messages to different outputs based on content evaluation

### Architecture

```
Input Message
    ↓
Evaluate Expression (JSONata)
    ↓ (returns string: case name or default)
Match Case Dictionary
    ↓ (case name → target route/sink)
Send to Target
    ├─ "order-large" → route_high_value
    ├─ "order-small" → route_standard
    └─ (default) → route_fallback
```

### Configuration

```yaml
steps:
  - route:
      expr: "status"  # JSONata expression evaluating to case name
      cases:
        "premium":
          target: route_vip_processing
        "standard":
          target: route_normal_processing
      default: route_fallback  # fallback if no case matches
```

### Implementation Plan

**File:** `internal/steps/route.go`

```go
type RouteStep struct {
    evaluator *expr.Evaluator
    cases     map[string]string  // case name → target (route or sink name)
    default   string             // fallback target
}

func NewRouteStep(expr string, cases map[string]string, default string) (*RouteStep, error)

func (rs *RouteStep) Execute(ctx context.Context, msg *Message) (*Message, error)
    // Returns: (msg, nil) with msg.Metadata.Route set to target
    // Error: if expr fails, if case not found and no default
```

**Key Decision:** 
- Route step *sets* the target route (via metadata), doesn't directly send
- Executor will handle routing based on metadata (M0.2.7 multi-route)
- Phase 0: Route step modifies metadata; message continues through pipeline

**Tests Required:** (5+)
1. Expression evaluates to matching case
2. Expression evaluates to missing case → uses default
3. Missing default with no matching case → error to DLQ
4. Complex expression (nested fields, functions)
5. Metadata route field updated correctly

**Exit Criteria:**
- ✅ Expression evaluates to case name
- ✅ Case name mapped to target
- ✅ Missing case → uses default
- ✅ No default + no match → error
- ✅ 5+ tests passing

**Blockers for M0.2.7:** None (Route step is independent)

## M0.2.4: Wiretap Step (Message Duplication)

**Purpose:** Copy message to secondary sink without altering main flow

### Architecture

```
Input Message
    ↓
Duplicate Copy (deep copy)
    ↓
Send Copy to Tap Sink (async, doesn't block)
    ↓
Return Original (unchanged)
```

### Configuration

```yaml
steps:
  - wiretap:
      sink: audit_log  # Named sink to copy messages to
```

### Implementation Plan

**File:** `internal/steps/wiretap.go`

```go
type WiretapStep struct {
    sinkName string
    // Reference to output sink (set during pipeline build)
    sink *Channel  // or adapter.SinkAdapter interface
}

func NewWiretapStep(sinkName string) (*WiretapStep, error)

func (ws *WiretapStep) Execute(ctx context.Context, msg *Message) (*Message, error)
    // 1. Deep copy message
    // 2. Send copy to sink (non-blocking, log errors but don't fail)
    // 3. Return original unchanged
```

**Key Decisions:**
- Non-blocking tap (send to sink doesn't block main flow)
- Tap failure is logged but doesn't fail the message
- Uses channel.TrySend() or async send to avoid blocking

**Tests Required:** (3+)
1. Message copied to tap sink
2. Original message continues unchanged
3. Tap sink error doesn't block main flow

**Exit Criteria:**
- ✅ Message copied to tap sink
- ✅ Original continues downstream
- ✅ Tap failure doesn't block main
- ✅ 3+ tests passing

**Blockers for M0.2.7:** None (Wiretap is orthogonal)

## M0.2.5: Idempotent Step (Deduplication)

**Purpose:** Suppress duplicate messages using a deduplication key

### Architecture

```
Input Message
    ↓
Extract Key (JSONata expression)
    ↓
Check Dedup Set (in-memory map)
    ├─ Key seen before → Drop (return nil)
    └─ Key is new → Add to set, Pass through
    ↓
TTL Eviction (background goroutine, default 1 hour)
```

### Configuration

```yaml
steps:
  - idempotent:
      key_expr: "transaction_id"  # JSONata expression to extract unique key
      ttl_minutes: 60             # How long to remember keys (default 60)
```

### Implementation Plan

**File:** `internal/steps/idempotent.go`

```go
type IdempotentStep struct {
    evaluator *expr.Evaluator
    keySet    map[string]time.Time  // key → expiry time
    lock      sync.RWMutex          // protect keySet
    ttl       time.Duration
}

func NewIdempotentStep(keyExpr string, ttlMinutes int) (*IdempotentStep, error)

func (is *IdempotentStep) Execute(ctx context.Context, msg *Message) (*Message, error)
    // 1. Evaluate key expression
    // 2. Check if key in set (with TTL check)
    // 3. If present and not expired → return nil (drop)
    // 4. If new → add to set with expiry → return msg
    // Eviction: background goroutine cleans expired keys periodically
```

**Key Decisions:**
- In-memory set only (distributed dedup is M0.3+)
- TTL-based eviction (not LRU, for predictability)
- Thread-safe with RWMutex (high read volume expected)
- Bounded set size warning (log if set > 100k keys)

**Tests Required:** (4+)
1. Duplicate key → dropped
2. Unique key → passed through
3. TTL expiry → key can be reused
4. Large dedup set doesn't crash (bounded)

**Exit Criteria:**
- ✅ Duplicate keys dropped
- ✅ Unique keys pass through
- ✅ In-memory set with TTL eviction
- ✅ Large sets handled (warning if needed)
- ✅ 4+ tests passing

**Blockers for M0.2.7:** None (Idempotent is orthogonal)

## M0.2.6: Authorize Step (RBAC/ABAC)

**Purpose:** Enforce RBAC or ABAC policies based on principal

### Architecture

```
Input Message (with principal in metadata)
    ↓
Extract Principal (from message.Metadata.Principal)
    ↓
Evaluate Policy
    ├─ RBAC: Check principal.Roles against require_roles
    └─ ABAC: Evaluate JSONata predicate with principal in scope
    ↓
Policy Decision
    ├─ ALLOW → Pass message through
    └─ DENY → Error to DLQ (auth error classification)
```

### Configuration

```yaml
steps:
  - authorize:
      mode: rbac
      require_roles:
        - admin
        - data-processor
      # OR
      mode: abac
      expr: "principal.roles contains 'admin' || principal.attributes['dept'] == 'finance'"
```

### Implementation Plan

**File:** `internal/steps/authorize.go`

```go
type AuthorizeStep struct {
    mode         string   // "rbac" or "abac"
    requireRoles []string // for RBAC
    evaluator    *expr.Evaluator // for ABAC
}

func NewAuthorizeStep(mode string, requireRoles []string, abacExpr string) (*AuthorizeStep, error)

func (as *AuthorizeStep) Execute(ctx context.Context, msg *Message) (*Message, error)
    // 1. Extract principal from msg.Metadata.Principal
    // 2. If nil → error (unauthorized)
    // 3. If RBAC → check principal.Roles
    // 4. If ABAC → evaluate expression with principal in scope
    // 5. If allowed → return msg
    // 6. If denied → return error (classification: "authorization_denied")
```

**Key Decisions:**
- Principal is mandatory (nil → deny)
- RBAC: exact role match
- ABAC: JSONata predicate with principal in scope
- Deny errors are classified as "authorization_denied" (not transient)

**Tests Required:** (5+)
1. RBAC: role present → allowed
2. RBAC: role missing → denied
3. ABAC: expression true → allowed
4. ABAC: expression false → denied
5. No principal → denied

**Exit Criteria:**
- ✅ RBAC checks principal roles
- ✅ ABAC evaluates JSONata predicate
- ✅ Denied → error to DLQ
- ✅ No principal → denied
- ✅ 5+ tests passing

**Prerequisite:** Principal propagation in HTTP source (M0.2.2+ enhancement; coordinate with that team)

**Blockers for M0.2.7:** Needs principal to be populated by HTTP source (may need M0.2.2 coord)

## M0.2.7: Multi-Route Support (Orchestration)

**Purpose:** Run multiple independent pipelines from single config file

### Architecture

```
Config File
    ↓
Parse Multiple Routes: route1, route2, route3, ...
    ↓
HTTP Source (shared) ← Listens on single port
    ↓ (routes messages based on route header/metadata)
Executor 1 ← steps for route1
Executor 2 ← steps for route2
Executor 3 ← steps for route3
    ↓ (each sends to their sink)
Sink 1, Sink 2, Sink 3, ...
```

### Configuration

```yaml
version: 1
sources:
  http-source: { type: http }

sinks:
  output1: { type: file, path: ./route1-output.jsonl }
  output2: { type: file, path: ./route2-output.jsonl }
  errors:  { type: file, path: ./errors.jsonl }

routes:
  route1:  # First pipeline
    from: http-source
    auth: none
    error_path: { target: errors }
    steps: [...]

  route2:  # Second pipeline (independent)
    from: http-source
    auth: none
    error_path: { target: errors }
    steps: [...]
```

### Implementation Plan

**Files:**
- `internal/factory/pipeline.go` (update BuildPipeline to handle multiple routes)
- `cmd/midctl/main.go` (update run command)

```go
// BuildPipeline extended to handle multiple routes
func BuildPipeline(ctx context.Context, cfg *config.RouteConfig) (
    executors map[string]*Executor,  // route name → executor
    sources []*SourceAdapter,         // shared source(s)
    sinks []*SinkAdapter,            // all sinks
    error,
)
```

**Key Decisions:**
- Single HTTP source shared across routes
- Each route gets its own executor
- HTTP requests specify route via header or metadata
- All routes share same error sink
- Graceful shutdown: stop all executors together

**Steps:**
1. Config loader: Parse multiple routes (done in M0.1.8)
2. Factory: Instantiate N executors from M routes
3. Source router: Route incoming messages to correct executor
4. Lifecycle: Start/stop all executors together

**Tests Required:** (4+)
1. Config with 2 routes loads correctly
2. Messages routed to correct executor
3. Each route processes independently
4. Shutdown stops all routes together

**Exit Criteria:**
- ✅ Config can define multiple routes
- ✅ Each route independent executor
- ✅ Messages routed correctly
- ✅ Routes process concurrently
- ✅ Coordinated shutdown
- ✅ 4+ tests passing

**Dependencies:** Needs M0.2.3-6 complete (all step types)
