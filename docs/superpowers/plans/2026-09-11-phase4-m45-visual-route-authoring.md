# Phase 4, M4.5 — Local, File-Based Visual Route-Authoring Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a local web UI (`dimctl studio`) that allows domain engineers to author, edit, and validate routes visually while preserving hand-edited YAML comments and structure (lossless round-tripping).

**Architecture:** A local CLI command that:
1. Serves a web UI on a local port (e.g., `http://localhost:3000`)
2. Reads/writes route YAML files directly from the working directory
3. Renders step DAG as an interactive node-graph
4. Generates forms from `schemas/route.schema.json`
5. Embeds JSONata text editor with syntax highlighting
6. Validates every save through `dimctl validate` before writing to disk
7. Optionally pairs with Tier 1 viewer to show live route state

**Tech Stack:** 
- Backend: Go (CLI command + HTTP server)
- Frontend: React + TypeScript (local web UI)
- Libraries: `go-yaml` (YAML round-tripping), `react-flow-renderer` (DAG visualization), `monaco-editor` (JSONata editing)

**Spec:** `design/phase-4-implementation-plan.md` (M4.5, §5), `visual-route-builder-feasibility-analysis.md` (§4), existing `schemas/route.schema.json` and Tier 1 viewer.

---

## Global Constraints

- **Lossless round-tripping:** Hand-edited YAML comments, blank lines, and key ordering must survive visual edit → save → read cycle
- **No concurrent editing:** Single-user local workflow only (no multi-user, no conflict resolution)
- **No new infrastructure:** Uses existing `dimctl validate`, JSON schema, observability infrastructure
- **Schema-driven:** Forms generated from schema, never hand-maintained
- **Validation gate:** Every save passes through `dimctl validate` (and optionally `dimctl test`)
- **Graceful degradation:** Tier 1 viewer integration is optional; studio works without it

```typescript
type FormFieldType = "text" | "number" | "select" | "textarea" | "checkbox";

function inferFieldType(schema: JSONSchema): FormFieldType {
  if (schema.type === "string") return "text";
  if (schema.type === "number") return "number";
  if (schema.enum) return "select";
  if (schema.type === "boolean") return "checkbox";
  return "textarea"; // fallback for objects
}

export function useSchemaForm(schema: JSONSchema, value: any, onChange: (value: any) => void) {
  return { fieldType: inferFieldType(schema), value, onChange };
}
```

```go
// POST /api/save
// Body: { route: RouteConfig, filePath: string }

func (s *StudioServer) SaveRoute(w http.ResponseWriter, r *http.Request) {
    var req struct {
        Route    config.RouteConfig `json:"route"`
        FilePath string              `json:"filePath"`
    }
    json.NewDecoder(r.Body).Decode(&req)
    
    // Validate route
    cfg, err := config.LoadRouteConfig(req.FilePath)  // Load to check schema
    if err != nil {
        // Return validation errors
    }
    
    // Write YAML back (preserving comments via YAML round-trip)
    yamlBytes, _ := marshalYAMLPreserveComments(req.Route, originalBytes)
    ioutil.WriteFile(req.FilePath, yamlBytes, 0644)
    
    // Validate auth declarations
    authErrors := config.ValidateAuthDeclarations(cfg, config.AuthValidationWarn)
    
    // Return result
    json.NewEncoder(w).Encode(map[string]interface{}{
        "valid": err == nil && authErrors == nil,
        "errors": collectErrors(err, authErrors),
    })
}
```

- [ ] **Step 2: Implement StudioServer**

```go
type StudioServer struct {
    currentFile string
    router      *http.ServeMux
}

func (s *StudioServer) Start(port int, openBrowser bool) error {
    s.router = http.NewServeMux()
    
    // API endpoints
    s.router.HandleFunc("/api/route", s.GetRoute)
    s.router.HandleFunc("/api/save", s.SaveRoute)
    s.router.HandleFunc("/api/schema", s.GetSchema)
    s.router.HandleFunc("/api/validate", s.ValidateRoute)
    
    // Serve embedded web UI (static files)
    s.router.HandleFunc("/", serveWebUI)
    
    addr := fmt.Sprintf(":%d", port)
    fmt.Printf("Studio running at http://localhost:%d\n", port)
    
    if openBrowser {
        exec.Command("open", fmt.Sprintf("http://localhost:%d", port)).Run()
    }
    
    return http.ListenAndServe(addr, s.router)
}
```

## Summary

**M4.5 establishes the visual-authoring pillar** of Phase 4 self-service. By providing a local, file-based web UI that preserves hand-edited YAML and validates every save, domain engineers can author routes visually while retaining the safety guarantees of the configuration-as-code model. The spike validates the feasibility of lossless YAML round-tripping before committing to the full implementation — a critical risk mitigation matching the discipline Phase 3's M3.1.1 established.

**Architecture principles:**
- Local-first: files read/written to disk, no remote state
- Schema-driven: forms generated, never hand-maintained
- Validation gate: every save passes `dimctl validate`
- Lossless round-trip: comments and formatting preserved
- Optional integrations: Tier 1 viewer, visual JSONata (no point-and-click)
